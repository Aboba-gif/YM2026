# Восстановление шести профилей источника

Эксперимент восстанавливает q(t) при заданном уравнении переноса и сравнивает
L² и полную H¹-регуляризацию. [Конфигурация](configs/experiment.json) задаёт
шесть аналитических профилей, восемь реализаций шума, сетки, базисы, наблюдения,
ковариационные веса и процедуру выбора α.

В основной серии одна сетка прямой задачи `G0` используется для генерации
наблюдений и восстановления. Пространственный оператор наблюдений имеет
гауссово ядро шириной 1 км. В других условиях меняются сетка генератора, веса, масштаб и
корреляция ошибок, доступность постов, пропуски, временное усреднение, базис,
реакция и временной масштаб штрафа. В каждой паре оба штрафа используют одни
и те же данные. Условия сравнения заданы в `analysis_contrasts`.

PG10 и SB150 — прямоугольные импульсы длительностью 10 и 150 минут;
EC04 и EC06 — суммы двух экспонент; J2 — два прямоугольных импульса,
S2 — два гладких импульса приподнятого косинуса. Все профили имеют
одинаковый заданный интеграл на интервале от 0 до 3 часов.

Полная H¹-регуляризация включает интеграл квадрата профиля и интеграл
квадрата его производной с множителем `tau_hours`². Матрицы штрафов
определены в [руководстве сравнения регуляризаций](../source_comparison/README.md).

## Единицы и ошибки источника

Время профиля измеряется в часах, интенсивность — в C·км²/ч,
где C обозначает единицу концентрации модели. ``source_mass`` задаёт
интеграл профиля от 0 до 3 часов в C·км². Безразмерные коэффициенты
P1 умножаются на положительный масштаб $Q_{\mathrm{ref}}$ в единицах
интенсивности. Пусть $q$ — заданный источник, а $\widehat q$ —
восстановленный. Заданный профиль принадлежит $L^2(0,T)$,
а численное восстановление — выбранному пространству
$V\subset H^1(0,T)$ непрерывных кусочно-линейных профилей.
При $T=3$ часа основная ошибка и относительная норма определены как

$$
  E_q=\frac{\|\widehat q-q\|_{L^2(0,T)}}{Q_{\mathrm{ref}}\sqrt T},
  \qquad
  \mathrm{relative\_L2}=
  \frac{\|\widehat q-q\|_{L^2(0,T)}}{\|q\|_{L^2(0,T)}}.
$$

Второе отношение предполагает ненулевую норму заданного источника.
Оба отношения безразмерны. В численном коде время выражено в часах,
поэтому длительность в этой нормировке равна 3.

Калибровка использует 32 независимые панели ошибок четырёх постов и девяти
основных времён. Оценённые дисперсии и длины корреляции задают ковариацию
72 времён каждого поста в той же параметрической модели; короткие лаги
отдельно не калибруются. `Woracle` использует заданную генерирующую
ковариацию. При выборе постов или пропусках сначала выделяется главная
подматрица наблюдаемых координат, затем строится её обратное действие.

`template_config` создаёт незакреплённый шаблон с пустыми условиями.
Режим `fit_regime=primary` использует 36 строк, `dense` — 288, до
отбора постов и пропусков. `truth_grid` заменяет общую сетку генератора
для данного условия. Отдельные `single_fits` используют выбранную
регуляризацию базового условия: `fixed_alpha` сохраняет обычное начальное
приближение, `zero_start` явно задаёт нулевое.

## Входы и выбор α

`source_protocol` задаёт файл профилей и его контрольную сумму. Из общего
протокола E05 использует определения PG10, SB150, EC04 и EC06; дополнительные
профили `NEW-J2` и `NEW-S2` определены в `sources.py`. Сетки, шум, калибровка
и выбор регуляризации E05 задаются собственной конфигурацией. Одноимённые
разделы общего протокола относятся к `source_comparison`. Дополнительные
входы можно перечислить в `input_files`; в предоставленной конфигурации
этот список пуст. Пути разрешаются относительно конфигурации. Предусмотрены 360
последовательностей по 25 α и 12 отдельных проверок: 9012 попыток восстановления.
Калибровка ковариации использует 32 независимых массива ошибок формы 4×9.
При пропусках сначала выбирается подматрица ковариации, затем она обращается.

Выбор α использует MSE на данных выбора. Ошибка относительно заданного q(t)
и проверочные концентрации в выборе не участвуют. Среди значений в заданном
численном допуске выбирается наибольшее α. Все выборы группы фиксируются
до вычисления проверочных ошибок.

В парный анализ включаются процедуры, у которых приняты все 25 кандидатов,
выбранное α лежит внутри заданного диапазона и итоговая проверка условий
Каруша — Куна — Таккера и прямой невязки пройдена. Пара учитывается,
если эти условия выполнены для обеих оценок и доступны обе записи
проверочных ошибок. Отказы калибровки, отклонённые
кандидаты, граничный выбор α и незавершённые случаи сохраняются в учёте полноты.

## Запуск и продолжение

Из папки проекта в PowerShell:

```powershell
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
python -X utf8 -B -m experiments.source_recovery --help
python -X utf8 -B -m experiments.source_recovery --config experiments/source_recovery/configs/experiment.json --source PG10 --replicate 8
```

Без `--source` и `--replicate` выполняется вся предусмотренная серия.
Полный запуск содержит тысячи численных решений. Поле `output` задаёт каталог
результатов; по умолчанию это `YM2026-results/source_recovery` рядом с папкой
проекта. Завершённый результат этой серии служит входом E06.

После каждой попытки сохраняется контрольная запись. Повтор команды продолжает
расчёт только при совпадении кода, конфигурации, входов и вычислительных
зависимостей. При продолжении незавершённой группы входные панели воспроизводятся
по тем же ключам; сохранённые кандидаты не пересчитываются. Завершённая
группа возвращается без повторного оценивания. Для иных входов нужен новый каталог вывода.

Независимые группы можно запускать параллельно. Инициализация общего `run.json`
последовательно выполняется под `.run.lock`; блокировка освобождается перед
работой групп. Файл `replicate_N.json.lock` предотвращает одновременную запись той же
группы другим процессом до окончания запуска. При завершении или обрыве процесса ОС освобождает
блокировку; её файл сохраняется для следующего запуска.

## Анализ записей

```text
python -X utf8 -B -m experiments.source_recovery.analysis.summary --run RUN_DIR --main-condition main --output SUMMARY_FILE
python -X utf8 -B -m experiments.source_recovery.analysis.plots --summary SUMMARY_FILE --output-dir FIGURE_DIR
```

`RUN_DIR` — каталог контрольных записей; `SUMMARY_FILE` — новый файл сводки,
`FIGURE_DIR` — новый каталог рисунков. После изменения анализатора сначала
создайте новую сводку: перед построением рисунков проверяется записанная
в ней контрольная сумма кода анализатора.
Готовые результаты восстановления при этом только читаются.
Сводка сохраняет ожидающие и отклонённые случаи в предусмотренных знаменателях.
Для рисунков требуется завершённая серия.

Спектр чувствительности приводится в исходных узловых координатах
и в координатах, ортонормированных по L² профиля. Второй спектр учитывает
матрицу интегрального штрафа и предназначен для сравнения базисов.
Численный ранг зависит от указанного порога; исходный спектр также
зависит от выбранного базиса.

После завершения предусмотренных последовательностей выбранные записи
фиксируются контрольной суммой; запись может содержать численные отказы.
Проверочные ошибки вычисляются после этой фиксации. Запись параметров
источника приводится к стандартным типам JSON перед каноническим
хешированием.

Число независимых повторов — число реализаций шума, а не число α.
Средние и стандартные ошибки относятся к принятым парам указанного плана.
Условия стационарности не доказывают глобальность минимума, существование
или устойчивость непрерывной обратной задачи.
