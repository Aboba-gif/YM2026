# Сопоставление с эпизодами КрАЗ

Эксперимент сопоставляет отклики заданной полулинейной модели с непересекающимися
трёхчасовыми эпизодами исходных измерений КрАЗ. Он использует профили
из [source_comparison](../source_comparison/README.md); восстановление физической
истории выбросов предприятия этой процедурой не выполняется.

Здесь используется отдельная постановка `source_comparison`, отличающаяся
от основной серии E05/E06 областью и нормировкой. Конфигурация предусматривает
четыре профиля источника и раздельный поиск в 2019–2021 годах и в 2022 году.

## Входы и запуск

[Конфигурация](configs/experiment.json) задаёт `simulation_config`,
`data_root`, `output`, множители профилей и периоды поиска. Все пути разрешаются
относительно конфигурации. Загрузчик требует 16 исходных CSV всех четырёх
постов; для поиска используются только наблюдения КрАЗ. Заполненные значения
в поиск эпизодов не включаются.

Из папки проекта:

```text
python -X utf8 -B -m experiments.kraz_alignment --help
python -X utf8 -B -m experiments.kraz_alignment --config experiments/kraz_alignment/configs/experiment.json
```

Расчёт создаёт модельные отклики и ищет окна в многолетнем ряду измерений.
Для результата нужен новый каталог `output`. Поиск окон и решение уравнения
не выполняются при вызове `--help`.

## Подгонка и проверка

Начала окон расположены через три часа на исходной временной сетке. В каждом
окне используются девять измерений через 20, 40, …, 180 минут после его начала.
Все они должны быть конечными; размах первых шести должен быть не меньше
`minimum_fit_range` — по умолчанию 10 единиц исходного CSV. Последнее измерение
должно строго предшествовать правой границе периода поиска. По первым шести
измерениям выбираются окно, множитель профиля q(t) и неотрицательная постоянная
добавка к концентрации. Критерий поиска — сумма квадратов невязок подгонки,
нормированная на сумму квадратов отклонений первых шести наблюдений от среднего.
При равенстве критерия окно выбирается по хронологическому порядку,
а множитель — по порядку шаблонов в конфигурации.

Для каждого множителя источника заново решается полулинейная прямая задача;
концентрация не получается простым умножением одного отклика. По умолчанию
перебираются множители 0,5; 1; 2; 4. Поле `amplitude_grid_edge` отмечает
выбор края этой сетки.

Подгонка использует времена +20, …, +120 минут. Контрольные измерения
при +140, +160 и +180 минутах не участвуют в подгонке: их наличие требуется
для допуска окна. Их значения не влияют на выбор окна, множителя и добавки;
они используются при последующей оценке и отображении результатов.
На них вычисляются RMSE
модельного прогноза и постоянного прогноза, равного среднему первых шести.
Календарное окно выбирается перебором. Время начала импульса внутри
заданного профиля, его длительность и метеорологические параметры
при этом не подбираются.

## Рисунки сохранённого расчёта

```text
python -X utf8 -B -m experiments.kraz_alignment.plots --config CONFIG_FILE --input RUN_DIR --output FIGURE_DIR
```

`CONFIG_FILE` — исходная конфигурация расчёта; `RUN_DIR` содержит завершённый
`manifest.json` и таблицы; `FIGURE_DIR` — новый каталог. Команда читает
сохранённые отклики, проверяет контрольные суммы и создаёт рисунки и
побайтовые копии пяти CSV. Уравнение и подбор параметров повторно не решаются.

Столбцы рисунка соответствуют порядку периодов в `selected_windows.csv`.
Вверху показан заданный профиль источника q(t) в C·км²/ч, где C — единица
концентрации сценарной модели. Это двумерная интенсивность источника,
а не полный массовый расход предприятия. Внизу синяя линия — прогноз
с выбранным множителем и добавкой, серая штриховая — прогноз с множителем 1
и собственной неотрицательной добавкой, отдельно выбранной по первым шести
измерениям, серая пунктирная — постоянный прогноз. Чёрные точки
обозначают первые шесть измерений, красные кресты — три отложенных.
Вертикальная линия отделяет участок подгонки. Даты, множители и ошибки
приведены в CSV. Краткие легенды обозначают линии и точки; условия
опыта описываются при вёрстке публикации.

## Результат

`templates.csv` содержит модельные отклики; `all_windows.csv` — рассмотренные
окна; `selected_windows.csv` — выбранные эпизоды; `overlays.csv` — наблюдения
и прогнозы; `summary.csv` — сводные ошибки. Отдельная запись сохраняет настройки
и контрольные суммы входов.

Часовой пояс и физические единицы исходных CSV не подтверждены. Числовое
сопоставление модельных откликов с CSV не устанавливает физическую
калибровку модели. Даже для более позднего периода выбор окна остаётся
поисковой процедурой.
Меньшая ошибка на трёх контрольных точках характеризует конкретный эпизод
и не устанавливает физическую идентифицируемость источника.
